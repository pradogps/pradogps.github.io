8  Dados organizados e combinação de tabelas

Pré-requisitos: Capítulo 7 · Pacotes: tidyr e dplyr (carregados com o tidyverse), readxl, here

Objetivos de aprendizagem

Ao final deste capítulo, espera-se que o estudante seja capaz de explicar o que são dados organizados (tidy data); converter tabelas entre os formatos longo e largo e reconhecer quando cada um é útil; separar e unir colunas; empilhar tabelas com a mesma estrutura; combinar tabelas por meio de chaves, escolhendo o tipo de junção adequado; conferir o resultado de uma junção; e reconhecer problemas de chaves comuns nos dados de saúde brasileiros.

Até aqui, cada análise usou uma única tabela. Mas muitos indicadores de saúde exigem informações que estão em fontes diferentes. A taxa de natalidade, por exemplo, precisa do número de nascidos vivos, que vem do SINASC, e da população, que vem das estimativas populacionais. Para combinar essas fontes, as tabelas precisam estar bem organizadas e precisam ter uma coluna em comum. Este capítulo trata das duas coisas.

library(tidyverse)
library(readxl)
library(here)
source(here("scripts", "preparar-sinasc.R"))

8.1 O que são dados organizados

Os mesmos dados podem ser dispostos em uma tabela de várias formas. Observe a planilha com a população dos municípios de Rondônia, importada no Capítulo 5.

populacao_anos <- read_excel(here("dados", "populacao_ro_2015_2024.xlsx"))

Cada linha é um município, e cada ano está em uma coluna. É um formato confortável para ler na tela, mas pouco prático para analisar. Como calcular, por exemplo, a população média de cada município no período, ou fazer um gráfico da população ao longo do tempo? A informação “ano” está espalhada nos nomes das colunas, e não em uma variável.

O conceito de dados organizados (tidy data), formalizado por WICKHAM (2014), propõe três regras simples. Cada variável fica em uma coluna. Cada observação fica em uma linha. Cada valor fica em uma célula. Na planilha acima, há três variáveis (município, ano e população), mas o ano não ocupa uma coluna própria. Organizá-la significa transformá-la em uma tabela com uma linha para cada combinação de município e ano. As ferramentas do tidyverse, incluindo o ggplot2, foram pensadas para trabalhar com dados nesse formato.

8.2 Do formato largo para o longo

A função pivot_longer(), do pacote tidyr, transforma colunas em linhas. Ela precisa de três informações: quais colunas serão empilhadas (cols), o nome da nova coluna que vai receber os antigos nomes de coluna (names_to) e o nome da coluna que vai receber os valores (values_to).

populacao_longa <- populacao_anos |>
  pivot_longer(
    cols = `2015`:`2024`,
    names_to = "ano",
    values_to = "populacao"
  )
populacao_longa

Os nomes das colunas começam com números, e por isso foram escritos entre crases. A tabela passou de 52 linhas e 12 colunas para 520 linhas e 4 colunas, uma para cada município em cada ano. Repare, porém, que a nova coluna ano é do tipo texto, porque veio dos nomes das colunas. O argumento names_transform converte o tipo no próprio pivot_longer().

populacao_longa <- populacao_anos |>
  pivot_longer(
    cols = `2015`:`2024`,
    names_to = "ano",
    values_to = "populacao",
    names_transform = list(ano = as.integer)
  )

Com os dados organizados, perguntas que antes eram difíceis ficam simples. Por exemplo, a variação percentual da população de cada município entre 2015 e 2024.

populacao_longa |>
  group_by(municipio) |>
  summarise(
    pop_2015 = populacao[ano == 2015],
    pop_2024 = populacao[ano == 2024],
    variacao_perc = (pop_2024 / pop_2015 - 1) * 100
  ) |>
  arrange(desc(variacao_perc)) |>
  head(5)

8.3 Do formato longo para o largo

O caminho inverso é feito com pivot_wider(), que espalha os valores de uma coluna em várias colunas. Ele é usado principalmente para montar tabelas de apresentação, que ficam mais fáceis de ler no formato largo. Os argumentos principais são names_from, a coluna cujos valores viram nomes de colunas, e values_from, a coluna cujos valores preenchem a tabela.

nascidos |>
  filter(!is.na(parto)) |>
  count(faixa_idade_mae, parto) |>
  pivot_wider(names_from = parto, values_from = n)
#> # A tibble: 3 × 3
#>   faixa_idade_mae Vaginal Cesáreo
#>   <fct>             <int>   <int>
#> 1 Menos de 20        2192    2359
#> 2 20 a 34            6062   13234
#> 3 35 ou mais          689    2443

O resultado é uma tabela de dupla entrada, com as faixas de idade nas linhas e os tipos de parto nas colunas. Quando alguma combinação não existe nos dados, a célula correspondente fica com NA; o argumento values_fill = 0 permite preenchê-la com zero, o que costuma ser o correto para contagens.

8.4 Separando e unindo colunas

As tabelas exportadas pelo TabNet trazem o código e o nome do município em uma única coluna, como 110001 Alta Floresta D'Oeste. Para combinar essa tabela com outras, precisamos do código em uma coluna própria. A função separate_wider_delim() divide uma coluna em várias a partir de um delimitador.

populacao_sexo <- read_csv2(
  here("dados", "tabnet_populacao_ro_2019.csv"),
  locale = locale(encoding = "latin1"),
  skip = 4, n_max = 52
)

populacao_sexo <- populacao_sexo |>
  separate_wider_delim(
    cols = Município,
    delim = " ",
    names = c("codigo", "nome"),
    too_many = "merge"
  )
populacao_sexo
#> # A tibble: 52 × 5
#>    codigo nome                  Masculino Feminino  Total

O delimitador é o espaço. Como os nomes dos municípios também têm espaços, usamos too_many = "merge", que divide a coluna apenas no primeiro espaço e mantém o resto junto. A operação inversa, juntar colunas em uma só, é feita com unite().

8.5 Empilhando tabelas

Quando duas tabelas têm as mesmas colunas e queremos colocar uma embaixo da outra, usamos bind_rows(). É o que acontece, por exemplo, quando os dados de cada ano ou de cada estado chegam em arquivos separados. O argumento .id cria uma coluna que identifica a origem de cada linha.

populacao <- read_csv(here("dados", "populacao_ro_2019.csv"),
                      col_types = cols(cod_municipio = col_character()))

feminina <- populacao |> filter(sexo == "Feminino") |> select(-sexo)
masculina <- populacao |> filter(sexo == "Masculino") |> select(-sexo)

bind_rows(Feminino = feminina, Masculino = masculina, .id = "sexo") |>
  count(sexo)
#> # A tibble: 2 × 2
#>   sexo          n
#>   <chr>     <int>
#> 1 Feminino    884
#> 2 Masculino   884

O exemplo é um pouco artificial, porque separamos uma tabela só para juntá-la de novo, mas mostra a lógica. As colunas são combinadas pelo nome, de modo que a ordem delas em cada tabela não importa.

8.6 Combinando tabelas por chaves

Chaves

Para combinar duas tabelas lado a lado, precisamos de uma ou mais colunas que identifiquem, nas duas tabelas, a mesma unidade. Essas colunas são chamadas de chaves. Em dados de saúde, as chaves mais comuns são o código do município, o código do estabelecimento de saúde e, em bases com identificação, o número do registro. Uma boa chave identifica cada linha de forma única em pelo menos uma das tabelas.

Vamos preparar as duas tabelas que queremos combinar. A primeira tem o número de nascidos vivos por município, calculado a partir do SINASC.

nv_municipio <- nascidos |>
  count(codmunres, munresnome, name = "nascidos_vivos")

A segunda tem a população total e a população feminina de 15 a 49 anos de cada município, calculadas a partir das estimativas populacionais.

pop_municipio <- populacao |>
  group_by(cod_municipio) |>
  summarise(
    mulheres_15_49 = sum(populacao[sexo == "Feminino" &
                                   faixa_etaria %in% c("15 a 19 anos", "20 a 24 anos",
                                                       "25 a 29 anos", "30 a 34 anos",
                                                       "35 a 39 anos", "40 a 44 anos",

A ordem das duas linhas dentro do summarise() não é um detalhe. As medidas são calculadas em sequência, e uma medida criada pode ser usada pelas seguintes. Se populacao = sum(populacao) viesse primeiro, a coluna populacao seria substituída pelo total do município, e o cálculo das mulheres de 15 a 49 anos passaria a usar esse total, e não os valores por sexo e faixa etária. O resultado estaria errado sem nenhum aviso. Por isso, quando uma medida reutiliza o nome de uma coluna, ela deve vir por último, ou receber outro nome, como pop_total.

Tipos de junção

O dplyr oferece quatro funções de junção que acrescentam colunas de uma tabela a outra. Elas diferem no que fazem com as linhas que não encontram correspondência.

A mais usada é left_join(), porque preserva a tabela principal da análise. As colunas que servem de chave são informadas no argumento by, com a função join_by(). Quando as chaves têm nomes diferentes nas duas tabelas, a correspondência é escrita com ==.

Vamos tentar combinar as duas tabelas.

nv_municipio |>
  left_join(pop_municipio, by = join_by(codmunres == cod_municipio))
#> # A tibble: 53 × 5

#>  1 110000    Município ignorado - RO              1             NA        NA
#>  2 110001    Alta Floresta D'Oeste              367             NA        NA
#>  3 110002    Ariquemes                         1729             NA        NA
#>  4 110003    Cabixi                              80             NA        NA
#>  5 110004    Cacoal                            1374             NA        NA
#>  6 110005    Cerejeiras                         237             NA        NA

A junção foi feita, mas a população veio toda como NA. Nenhum município encontrou correspondência. O motivo está na próxima seção.

8.7 Chaves em dados de saúde no Brasil

Compare os códigos das duas tabelas.

head(nv_municipio$codmunres, 3)
#> [1] "110000" "110001" "110002"
head(pop_municipio$cod_municipio, 3)
#> [1] "1100015" "1100023" "1100031"

O SINASC usa o código do município com seis dígitos, enquanto as estimativas populacionais usam o código com sete dígitos, definido pelo IBGE. O sétimo dígito é um dígito verificador. Essa diferença é uma das armadilhas mais comuns na combinação de bases de saúde brasileiras: muitos arquivos do DATASUS usam o código de seis dígitos, e a maior parte das bases do IBGE usa o de sete. A solução é criar, na tabela de população, uma coluna com os seis primeiros dígitos, usando str_sub() do pacote stringr (que será apresentado no Capítulo 9).

pop_municipio <- pop_municipio |>
  mutate(codmun6 = str_sub(cod_municipio, start = 1, end = 6))

indicadores <- nv_municipio |>
  left_join(pop_municipio, by = join_by(codmunres == codmun6))
indicadores

Agora a combinação funcionou. Outros problemas frequentes com chaves são a diferença de tipo (o código guardado como número em uma tabela e como texto na outra, o que faz o dplyr interromper a junção com um erro) e o uso de nomes como chave. Nomes de municípios não devem ser usados para combinar tabelas, porque a grafia varia entre fontes, com e sem acentos, com abreviações ou com apóstrofos diferentes, como em “Alta Floresta D’Oeste”.

Conferindo o resultado de uma junção

Toda junção deve ser conferida. Três perguntas ajudam. O número de linhas mudou? Se a tabela de destino tem mais linhas depois da junção, alguma chave estava repetida na outra tabela, e os registros foram duplicados. Há linhas sem correspondência? E, se há, por quê?

As junções de filtragem ajudam a responder à segunda pergunta. A função anti_join() devolve as linhas da primeira tabela que não têm par na segunda, e semi_join() devolve as que têm.

nrow(nv_municipio)
#> [1] 53
nrow(indicadores)
#> [1] 53

nv_municipio |>
  anti_join(pop_municipio, by = join_by(codmunres == codmun6))
#> # A tibble: 1 × 3
#>   codmunres munresnome              nascidos_vivos
#>   <chr>     <chr>                            <int>
#> 1 110000    Município ignorado - RO              1

O número de linhas se manteve, e apenas um registro ficou sem correspondência: o código 110000, de residência ignorada, que de fato não tem população associada. A junção está correta.

8.8 Estudo de caso: natalidade e fecundidade nos municípios de Rondônia

Com as duas tabelas combinadas, podemos calcular dois indicadores demográficos clássicos. A taxa bruta de natalidade é o número de nascidos vivos dividido pela população total, multiplicado por mil. A taxa de fecundidade geral é o número de nascidos vivos dividido pelo número de mulheres de 15 a 49 anos, também multiplicado por mil. A segunda é mais específica, porque relaciona os nascimentos apenas às mulheres em idade reprodutiva.

indicadores <- indicadores |>
  filter(codmunres != "110000") |>
  mutate(
    taxa_natalidade = nascidos_vivos / populacao * 1000,
    taxa_fecundidade_geral = nascidos_vivos / mulheres_15_49 * 1000
  )

indicadores |>
  select(munresnome, nascidos_vivos, populacao, taxa_natalidade, taxa_fecundidade_geral) |>
  arrange(desc(taxa_fecundidade_geral)) |>
  head(6)

#> 1 Guajará-Mirim             781     43841            17.8                   68.1
#> 2 Pimenteiras d…             40      2346            17.1                   67.1
#> 3 Buritis                   583     32152            18.1                   66.3

#> 5 São Francisco…            303     17379            17.4                   64.2

Para o estado como um todo, somamos numeradores e denominadores, como aprendemos no capítulo anterior. Os nascimentos com residência ignorada são de mães residentes em Rondônia e, por isso, entram no numerador estadual.

) |>

Por fim, uma tabela de apresentação dos municípios mais populosos, com os indicadores arredondados.

indicadores |>
  slice_max(populacao, n = 5) |>

A função transmute() funciona como mutate(), mas mantém apenas as colunas criadas. Os nomes entre crases permitem usar espaços e acentos nos títulos das colunas, o que é aceitável em tabelas de apresentação, mas deve ser evitado nas colunas usadas para análise.

Saúde Pública em foco

A qualidade de um indicador depende da qualidade do numerador e do denominador. Onde parte dos nascimentos não é registrada no SINASC, as taxas calculadas diretamente dos dados subestimam a realidade, e por isso a cobertura do sistema em cada local deve ser considerada antes de comparar indicadores. As estimativas populacionais, por sua vez, são projeções revisadas periodicamente, sobretudo depois de cada censo. Ao comparar indicadores de anos diferentes, convém verificar se as populações usadas vêm da mesma série de estimativas.

8.10 Síntese

Dados organizados seguem três regras: cada variável em uma coluna, cada observação em uma linha e cada valor em uma célula. A função pivot_longer() transforma tabelas largas, com variáveis espalhadas nos nomes das colunas, em tabelas longas, adequadas à análise; pivot_wider() faz o caminho inverso, útil para tabelas de apresentação. A função separate_wider_delim() divide uma coluna em várias, e bind_rows() empilha tabelas. As junções combinam tabelas por meio de chaves: left_join(), inner_join(), right_join() e full_join() acrescentam colunas, enquanto semi_join() e anti_join() filtram linhas. No Brasil, a diferença entre o código de município com seis dígitos, usado pelo DATASUS, e com sete dígitos, usado pelo IBGE, é a armadilha mais comum. Toda junção deve ser conferida quanto ao número de linhas e às linhas sem correspondência.
